## このLPの役割

名刺、SNS、紹介、検索、著書など複数の入口から訪れる人に向けた、後藤将哉の鮨・著者活動ポータル。本人と鮨の関係を伝え、著書 / 鮨講座 / 法人・コミュニティ向け開催相談 / LINE登録へ橋渡しするハブ。
軸メッセージ:「鮨は最強のコミュニケーションツール」「名刺交換だけでは記憶に残らない／自己紹介は仕込むもの」。

### 現状のセクション構成
1. Hero「後藤将哉」→ CTA『活動を見る』
2. #activities 活動の3入口（鮨を学ぶ / 鮨体験を開く / 本で知る）
3. #why なぜ鮨なのか（名刺交換の限界／鮨は関係性の入口）

7. 開催実績（鮨リトリート）
8. #book 著書『経営者こそ、鮨を握れ。』
9. #connect LINEとSNSの継続接点

継続接点用LINE: `https://sub.masaya-goto.com/line/open/P0vXoLHsEx3T`

### 4. 実績カードの型（1件あたり）
- 日付・会の名前（例: 鮨リトリート / 2026.4）
- 写真1枚
- 一行の「何が起きたか」＋特筆点（例: 『スタンフォード式 最高の休み方』著者・鈴木亜佐子氏を特別ゲストに迎えた回）
- 可能なら参加者の声を1つ（※原文のまま・改変厳禁）
- トーン: 控えめ・事実で語る。煽らない。鮨まさや／縁元の世界観に合わせる。

### 5. 流入経路の計測方針（URL・LINE登録URL）
- **LPは `/masaya` の1枚に統一。LPは複製しない**（複製は更新の二重管理で事故の元）。
- 分けるのは「流入経路」のみ。LPのURLに流入元パラメータを付ける（例: 名刺QR=`?src=meishi`、SNS=`?src=sns`）。
- **UTAGE側で流入経路別のLINE登録URL**を用意し、LPのLINEボタンを `?src` に応じて出し分ける（小さなJSで切替）。これで1枚のLPのまま名刺経由/SNS経由を別集計できる。
- JSを避けるなら最低限「名刺は現状維持＋SNS用に2本目のLINE登録URLを作る」でも計測は成立。
- ※UTAGEの流入経路別登録URL発行の実設定可否は、実装前にUTAGE側で確認する。

- status: confirmed
- scope_layer: copy / funnel / implementation
- objective: 守成クラブで自己紹介を聞き、名刺を受け取った経営者の関心を、書籍・鮨講座・LINEの次の接点へつなげる。
- reader_state:
  - who: 和田優喜子の紹介でゲスト参加した後藤将哉の自己紹介を聞いた経営者
  - state: 「趣味で鮨職人」「3時間で鮨が握れる」という意外性に興味を持っている
  - knows: 後藤将哉が経営者向けの鮨講座を運営していること
  - natural_next_action: 鮨によって出会い方が変わった理由と講座内容を知り、関心があれば次回案内を受け取る
- current_decision:
  - Heroの主訴求を、商品一覧から書籍由来の「鮨を握ったら、出会う人が変わった」へ変更する。
  - 「鮨が才能を引き出した」は本人の体験を説明する第2メッセージとして使い、読者全員への効果として約束しない。
  - プロフィール直後に3時間の実践講座セクションを追加する。
  - 講座後の変化は「持ち帰れる」「手に入る」ではなく、「自分で一貫を握って、家族や仲間にふるまえる」と具体的な動作で書く。
  - 終了済みの2026年7月30日講座LPへは直接送客せず、次回開催案内のLINEへつなぐ。
- rationale:
  - 書籍本文に「変化の本質は、人との『出会い方』」「鮨が、僕の中にあった才能を引き出してくれた」と明記されている。
  - 「3時間で握れる」は興味を作る具体的な入口として有効だが、単独で主訴求にすると料理教室に見えやすい。
  - 名刺QR用LPのポータル機能は維持し、鮨が仕事や出会いにつながる理由を先に理解させる。
- rejected_alternatives:
  - 「鮨であなたの才能を引き出す」をHeroで約束する: 読者全員への再現性を確認できておらず、約束が大きすぎる。
  - 「3時間で鮨が握れる」だけをHeroの中核にする: 技術講座として受け取られ、本来の出会い方・関係構築の価値が弱くなる。
